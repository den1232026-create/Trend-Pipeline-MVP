# Техническое задание: Trend → Meme Pipeline

**Проект:** `trend-meme-pipeline`  
**Заказчик:** GPTunneL (тестовое задание для стажировки)  
**Исполнитель:** Дмитрий  
**Дата:** 09.11.2026  
**Источник требований:** устное ТЗ от Тимофея (руководитель разработки), собеседование 09.11.2026

---

## 1. Цель

Собрать сервис, который:

1. **Рано** находит вирусные визуальные тренды в соцсетях (рилсы / шортсы / тиктоки, в т.ч. face-swap / AI-мемы).
2. **Автоматически** строит бюджетный пайплайн генерации (модели + референсы + пресет).
3. **Выдаёт готовый результат** — пресет на платформе, куда пользователь загружает своё лицо / лицо персонажа и получает готовый ролик или мем.

Ключевая ценность для GPTunneL: тренд пойман на ранней стадии → пресет уже готов к моменту пика → команда не дёргается ночью вручную.

---

## 2. Три «морды» (основные модули)

| # | Модуль | Суть |
|---|--------|------|
| 1 | **Парсер трендов** | Мониторинг соцсетей, поиск растущих трендов, референсы, предиктивный анализ |
| 2 | **Автосборка пайплайна** | По тренду выбрать модели (через API GPTunnel), референсы, промпты → пресет |
| 3 | **Готовый результат** | Упакованный пресет + демо-генерация (лицо → мем/видео) |

Обязательно: **backend + frontend**, интерфейс аккуратный и понятный.

---

## 3. Функциональные требования

### 3.1. Парсер трендов

- Источники (минимум 1–2 на MVP, лучше с возможностью расширения):
  - TikTok / YouTube Shorts / Instagram Reels / аналогичные публичные агрегаторы трендов (если прямой API недоступен — допустимы открытые рейтинги, хештеги, публичные страницы трендов).
- Определять признаки роста:
  - скорость набора просмотров / лайков / репостов (если доступно),
  - повторяемость формата (один и тот же паттерн у разных авторов),
  - ранние стадии (до массового пика).
- Для каждого найденного тренда сохранять:
  - название / краткое описание формата,
  - **референсы** (ссылки, превью, скриншоты или описание источника),
  - почему считается трендом (метрики / сигналы),
  - тип (face-swap, template-мем, motion template и т.п.),
  - оценка «ранней стадии» (score / статус: emerging / rising / peak).
- Предиктивный слой (LLM):
  - почему тренд может вырасти,
  - для какого пресета на GPTunnel он подходит,
  - краткий бриф для пайплайна.

### 3.2. Автоматическое построение пайплайна

- На вход: карточка тренда + референсы + анализ LLM.
- На выход: **пресет**, включающий:
  - список шагов пайплайна (какие модели, в каком порядке),
  - промпты / параметры,
  - какие входы нужны от пользователя (своё лицо, лицо персонажа, фон и т.д.),
  - ожидаемый тип выхода (картинка / короткое видео),
  - оценку стоимости одного прогона (в рамках бюджета).
- Модели и API: **GPTunnel** (ключ и лимит выдаёт Тимофей; ориентир бюджета **до ~500 ₽** на эксперименты — выбирать бюджетные модели).
- Пайплайн должен собираться **автоматически** (без ручной настройки команды) после обнаружения тренда.
- Желательно: возможность запуска по расписанию / в фоне (в т.ч. «ночью»), чтобы пресет появлялся сам.

### 3.3. Готовый результат (упаковка)

- Пользователь в UI видит список трендов / пресетов.
- У пресета: описание, референсы тренда, почему выбран, схема пайплайна.
- Действие пользователя: загрузить лицо(а) → запустить генерацию → получить готовый мем/ролик (или понятный статус ошибки).
- Демо-режим допустим на MVP: если полноценное видео дорого/сложно — минимум 1 рабочий end-to-end сценарий (хотя бы image face-swap / template), с честным указанием ограничений.

### 3.4. Frontend / Backend

- **Backend:** API для трендов, пресетов, запуска генерации, статусов задач, хранения артефактов.
- **Frontend:** список трендов, карточка тренда+пресета, загрузка лиц, просмотр результата, базовый статус пайплайна.
- UI должен быть «красиво» в смысле продукта: чисто, читаемо, без ощущения сырого скрипта.

---

## 4. Нефункциональные требования

- Бюджет API: **до ~500 ₽** (GPTunnel), приоритет — дешёвые модели.
- Самостоятельность: разбор документации и кода своими силами; уточнения у Тимофея — по делу, в Telegram.
- Код: понятная структура папок, README с запуском, без секретов в репозитории (`.env.example`).
- Прозрачность решений: в UI или в карточке тренда видно **откуда** взяли тренд и **почему** собрали именно такой пайплайн.

---

## 5. MVP vs желаемое

### MVP (обязательно для сдачи)

1. Рабочий поток: **найти/завести тренд → анализ → пресет → генерация демо-результата**.
2. Хотя бы один источник трендов (даже если частично полуавтомат / с seed-данными + один живой источник).
3. Референсы и объяснение «почему тренд».
4. Автогенерация описания пайплайна (модели + промпты) через LLM + GPTunnel API.
5. Frontend + Backend, один сценарий end-to-end.
6. README: как запустить, какой ключ куда положить, как проверить.

### Nice-to-have (если успеется)

- Полностью фоновый крон-парсинг нескольких сетей.
- Очередь задач, вебхуки статусов.
- Несколько типов пресетов (image / video).
- Сравнение «цена / качество» моделей при выборе пайплайна.
- Кэш результатов и дедуп трендов.

## 6. Ограничения и допущения

- Прямой официальный API TikTok/Instagram может быть недоступен или дорог — допустимы легальные обходные источники (публичные рейтинги, RSS, агрегаторы, ручной seed + полуавтомат). **Без нарушения ToS / скрапинга закрытых данных** там, где это критично; в README явно указать источники.
- Face-swap / deepfake-подобные сценарии — только как демо шаблонов трендов, без вредоносного использования чужих лиц без согласия.
- Юридическое оформление стажировки — отдельно, после прохождения тестового (по словам Тимофея).

---

## 7. Критерии приёмки

Считается выполненным, если:

1. Можно открыть UI и увидеть тренды с референсами.
2. По тренду автоматически (или одной кнопкой «собрать») появляется пресет пайплайна.
3. По пресету можно загрузить лицо и получить **готовый визуальный результат** (или понятный pipeline-статус с артефактом).
4. Видно, откуда тренд и почему выбран пайплайн.
5. Использован API GPTunnel в разумном бюджете.
6. Есть инструкция запуска и краткая оценка сроков (см. ниже).

## 9. Предлагаемый стек (рекомендация, не жёсткое требование)

- **Backend:** Node.js + TypeScript (или Python, если удобнее для парсинга/ML-утилит).
- **Frontend:** простой современный UI (React/Next или лёгкий SPA).
- **Хранение:** SQLite/Postgres + файлы артефактов локально.
- **Очередь (опционально):** in-process / BullMQ.
- **LLM + gen:** GPTunnel API.
- **Конфиг:** `.env` (ключ GPTunnel, лимиты).

Стек можно менять, если аргументировать в README.
